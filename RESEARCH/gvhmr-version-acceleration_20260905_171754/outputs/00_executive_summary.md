# 결론

현재 설치된 공식 GVHMR 코드는 최신 main과 같다: `6ec3ca3`, 2026-05-21. 서버 git과 공식 원격 참조를 직접 비교했다. 구버전 교체가 해법인 상황은 아니다. [src_001] [src_002]

가속을 구현한 공개 프로젝트는 있다. `ryanrudes/gvhmr`는 모델 재사용·로딩 최적화·fused attention·혼합정밀도를 구현한 Python 포크다. [src_004] [src_018] [src_019]
NVIDIA GENMO에는 현재 쓰는 ViTPose-H/HMR2 체크포인트를 대상으로 한 ONNX export와 TensorRT/ONNX 실행 코드가 있다. 단, GENMO의 본체는 다른 모델이므로 전처리 기법 참고용이지 GVHMR 전체 교체품이 아니다. [src_007] [src_008] [src_009]

추천 방향은 엔진을 통째 교체하는 것이 아니라, 같은 계산의 준비·데이터 전달 낭비를 먼저 줄이고 전처리 backend를 비교 검증하는 것이다. C++라는 언어 자체가 무조건 빠르거나 품질 보존을 보증하지 않는다. [src_012] [src_013]

## 미확정 / 확인 필요

완성형 GVHMR C++ 포팅과 전체 모션 동등성 검증까지 갖춘 공개 구현은 이번 검색에서 확인하지 못했다. 존재하지 않는다는 뜻은 아니다.
포크 작성자는 RTX 6000 Ada에서 긴 클립 약 3–4배 향상을 보고한다. 우리 RTX 3070에서의 속도·접지·이동 경로·떨림 보존은 재현하지 않았다. [src_004] [src_005] [src_006]
NVIDIA 예제에는 비상업 사용 제한이 있는 라이선스가 명시되어 있다. 제품 편입 허용 여부는 별도 검토가 필요하다. [src_017]

연구 기록만 만들었으며 설치·모델 변경·GPU 실험·서비스 업데이트는 하지 않았다.
