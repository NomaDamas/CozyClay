# GVHMR의 중력 표현과 낙하 복원 — 2026-09-05
결론: Gravity-View는 방향 기준이며 공개 추론 코드는 중력 힘을 적분하지 않는다. 중력 궤적 보정은 추가적인 복원 문제다. [src_001][src_003][src_007]

## 확인된 구조

| 단계 | 실제 동작 | 낙하에 대한 의미 |
|---|---|---|
| GV 자세 | 학습 때 중력 기준 좌표를 사용하고 추론 때 해당 좌표에 대한 자세를 예측 | 방향 정렬이지 중력 가속도 보장이 아님. [src_001][src_002][src_003] |
| 전역 이동 | SMPL 기준 프레임 변위를 월드 방향으로 회전·누적 | 원래 변위 추정이 작으면 큰 낙하를 표현하지 못할 수 있음. [src_001][src_008] |
| 정지 판정 | 손·발의 관절 속도로 만든 라벨을 예측 | 실제 지지력이나 나무·벽의 접촉 판정과 다름. [src_007][src_008] |
| 정적 카메라 후처리 | 카메라 공간과 월드 위치의 축별 오차가 25cm 이상이면 추가 수정을 프레임당 2cm 이내로 누적 | 전체 속도 제한이 아니라 오차를 따라잡는 수정 제한. 정지 관절 단계는 Y를 고치지 않음. [src_006][src_019] |
| 바닥 맞춤 | 시퀀스 전체 최저 높이를 기준으로 일정 오프셋 이동 | 모든 프레임의 실제 접촉을 복원하는 계산이 아님. [src_005][src_006] |

저자는 부유를 알려진 전역 이동 제약 문제로 설명했다. 같은 높이 바닥에 대한 선형 보정 예제는 제공하지만, 나무 지지·공중 비행 전체에 대한 해법은 아니다. [src_004][src_005]
현재 서버 HEAD와 공식 main은 6ec3ca3이며 후처리 파일 SHA256도 같다. 버전이 오래돼서만 발생한 현상으로 볼 근거는 없다. [src_018][src_019]
기존 나무 A/B 기록의 골반 하강량과 후처리 추가 root 이동량을 다시 계산했다. 상세 값은 local_audit.json에 보존했다. 이는 저장자료 재계산이지 새 모델 실행이 아니다. [src_009][src_019]
분석 시 translY의 root 이동과 pelvisY의 관절 위치를 구별했다. 후자는 IK/FK 자세 변화가 섞이므로 동일한 값으로 취급하면 안 된다. [src_007][src_009][src_019]

## 직접 관련된 연구와 코드

KungFuAthleteBot은 GVHMR→로봇 리타게팅 뒤 높이 극값·바닥 기준·포물선으로 점프를 정리한다. 논문에도 수동 skip 집합이 있고, 공개 코드에는 특정 극값 제외가 있다. [src_010][src_011][src_012]
코드 분석상 포물선은 원본 FPS를 받지 않는다. y0, y1, N을 고정하면 식은 y[k]=y0−(y0−y1)(k/(N+1))²가 되어 g가 상쇄된다. 모양은 포물선이어도 원본 재생시간의 실제 중력 가속도를 보장하지 않는다. 자체 산술검사도 일치했다. [src_010][src_011][src_019]
ICCV2019 연구는 관절 운동과 몸 전체 이동을 구별해 질량중심을 사용하고, 외력이 중력뿐인 구간에서 영상 궤적과 실제 단위를 연결한다. GraviCap도 자유 비행하는 물체 관측으로 중력 제약을 활용한다. 적용 조건은 서로 다르다. [src_013][src_014][src_017]
설계 판단: GVHMR 자세를 출발점으로 보존하고 지지 해제·공중·착지를 구분한 뒤, 공중 질량중심에 C(t)=C0+V0t+½gt²를 원본 타임스탬프·카메라·규모·2D 재투영과 함께 맞추는 방향을 권한다. 고정 초기속도 0이나 클립 전체 낙하는 가정하지 않는다.
비유하면 수평계로 방향만 맞추는 단계에, 공이 언제 손을 떠나 어디에 도달했는지의 관측과 낙하 법칙을 추가하는 것이다. 힘·카메라·시간 정보가 불확실한 영상은 물리 보정도 불확실하다고 표시해야 한다.
