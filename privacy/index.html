Privacy

Short version: anonymous usage counts, no cookies, no recordings, never your project content. Every part of it can be turned off.

Effective October 25, 2026

The website (cozyclay.org)

The site uses PostHog (US Cloud) for anonymous usage analytics and Cloudflare Web Analytics for page counts. There are no cookies and no session recording, and Do-Not-Track is respected. PostHog keeps a random pseudonymous identifier in your browser's localStorage so returning visits can be counted; it is never linked to an account or to anything you make, and clearing site data removes it. Country comes from ingest-time GeoIP only; no precise location is collected.

The in-browser playground on the home page runs the studio inside the page. It does not read or write your saved scenes, and nothing you build there leaves your browser unless you download it.

The npm package (npx cozyclay)

The official npm package measures anonymous first launches, sessions and an in-app usage funnel on its local studio. It stores one random installation identifier in ~/.config/cozyclay/state.json (or $XDG_CONFIG_HOME/cozyclay/state.json) so returning use can be counted across normal CLI restarts, ports and browser storage resets. The browser's memory-only SDK starts with this anonymous ID on each launch. Independent state files receive independent random IDs, without fingerprinting, account linking or cross-device matching; do not copy the state file between users. A copied start command such as npx cozyclay --via site stores that one source label with the first-launch receipt instead of asking where you heard about CozyClay. Prompt text, asset names, file names, project content, local paths and any user-entered text are never collected. Session duration and action counts are bucketed. Source checkouts, forks, development servers, CI and tests send nothing.

The package prints this disclosure once on first launch. Control it at any time:

cclay telemetry status
cclay telemetry off
cclay telemetry on

COZYCLAY_TELEMETRY=0 or DO_NOT_TRACK=1 disable collection for a launch. The topbar toggle inside the studio changes the same setting and removes the installation identifier. Enabling collection later creates a new, unlinked ID; the original first-launch receipt remains, so this does not create another new-install event. Environment overrides only suspend collection and do not erase the stored ID. Opting out also suppresses the session-end beacon.

Explicit internal and QA marking

Internal marking is optional and never enables telemetry. Use cclay telemetry internal on or cclay telemetry internal off to store the boolean internalQa in the npm CLI state file, then reload open studio tabs. For the hosted app, open https://cozyclay.org/app/?internal_qa=1 to mark that browser or ?internal_qa=0 to clear it. A single explicit 1 or 0 persists as cozyclay.internalQa in localStorage for that origin. The npm app uses only its CLI setting, not this URL parameter.

All app events and end beacons carry boolean internal_qa, false by default. External usage queries exclude only explicitly marked events; localhost, ports, country and source checkouts are never used to infer internal people. Unmarked local-app users remain included. Opt-out, Do-Not-Track, CI, origin restrictions and disabled builds still win. Historical unmarked QA cannot be retroactively distinguished.

Every regular app event and session-end beacon carries the same distribution (npm or hosted), app_version when available, origin_kind (local or hosted), internal_qa boolean, coarse operating-system label and, for npm sessions, install_kind (npx or global) and update_status (latest, outdated or unknown), read from the package's own cached update check. PostHog's free plan retains events for one year.

Workflow run_id, Agent turn_id and MCP request_id values are fresh random 32-character hexadecimal values held only for one execution. Execution telemetry contains only closed categories, outcomes and elapsed-time buckets; missing telemetry is left unknown, and a disconnected MCP editor is not backfilled.

The hosted demo (Google sign-in)

The hosted demo is not open to the public right now. This section describes what it handled while it was running. The hosted motion demo asks you to sign in with Google so that the daily generation cap can be enforced per account. It receives your Google account's email address and basic profile only, stores a session cookie signed by our server, and keeps your prompt and the generated result for up to 30 days so the ticket link keeps working. Results are stored on Cloudflare R2 and deleted after that window. The demo does not post to your account or read anything else from it. Cloudflare Turnstile is used to block automated submissions.
